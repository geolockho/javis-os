**Bạn:** Error: failed to create containerd task: failed to create shim task: OCI runtime create failed: runc create failed: unable to start container process: error during container init: exec: "/bin/sh": stat /bin/sh: no such file or directory. (0s)

**Javis:** ### Lỗi này nghĩa là gì

Container không chạy được vì image **không có `/bin/sh`**. Runtime cố chạy `/bin/sh` để thực thi lệnh (thường là `command: ["/bin/sh", "-c", ...]` hoặc một script shell), nhưng file đó không tồn tại trong image. Lỗi xảy ra ngay lúc khởi tạo (`0s`), nên pod không có log nào để xem.

Đây là lỗi hay gặp với image `distroless`, `scratch`, hoặc một số image tối giản.

### Nguyên nhân hay gặp

- Manifest dùng `sh -c` hoặc gọi script shell, nhưng image là distroless hoặc scratch.
- Image đã đổi sang bản không có shell, ví dụ đổi từ `alpine` hoặc `debian` sang bản tối giản.
- Đường dẫn shell khác, ví dụ image chỉ có `/bin/bash` hoặc `/usr/bin/sh`.

Lỗi này có thể liên quan đến job `etcd-snapshot` đang FAILED trước đó, nếu init container `snapshot` dùng `/bin/sh`.

### Cách kiểm tra (chỉ đọc)

```bash
kubectl --context=<ctx> -n <ns> get pod <ten-pod> -o jsonpath='{.spec.containers[*].image}{"\n"}{.spec.containers[*].command}{"\n"}{.spec.containers[*].args}{"\n"}'
kubectl --context=<ctx> -n <ns> get pod <ten-pod> -o jsonpath='{.spec.initContainers[*].image}{"\n"}{.spec.initContainers[*].command}{"\n"}'
```

Kiểm tra image có shell hay không:

```bash
docker run --rm --entrypoint /bin/sh <image> -c "echo ok"
# hoặc
docker run --rm --entrypoint ls <image> /bin /usr/bin
```

### Hướng xử lý

- Nếu chỉ cần shell: đổi sang image có shell (ví dụ `alpine`, `busybox`) hoặc dùng bản `:debug` của distroless.
- Nếu không cần shell: bỏ `sh -c`, gọi trực tiếp binary bằng dạng exec, ví dụ `command: ["/app/binary", "--flag"]`.
- Nếu là init container của cronjob etcd: kiểm tra xem `command` có dùng `/bin/sh` không, và đảm bảo image snapshot có shell.

Mình chưa chạy lệnh nào trên cụm. Nếu bạn gửi tên pod, namespace, context và kết quả lệnh jsonpath ở trên, mình sẽ xác định chính xác container nào đang gây lỗi và đề xuất sửa manifest.

```python
import subprocess, pathlib, datetime
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("may-ca-nhan")
LOG = pathlib.Path(r"D:\mcp-local\audit.log")

def audit(msg: str):
    with LOG.open("a", encoding="utf-8") as f:
        f.write(f"{datetime.datetime.now().isoformat()} {msg}\n")

@mcp.tool()
def run_command(command: str, cwd: str = "", timeout: int = 120) -> str:
    """Chạy lệnh PowerShell trên máy cá nhân. Trả về exit code, stdout, stderr."""
    audit(f"RUN cwd={cwd!r} cmd={command!r}")
    try:
        p = subprocess.run(
            ["powershell", "-NoProfile", "-Command", command],
            cwd=cwd or None, capture_output=True, text=True,
            timeout=timeout, encoding="utf-8", errors="replace",
        )
        return f"exit={p.returncode}\n--- stdout ---\n{p.stdout[-20000:]}\n--- stderr ---\n{p.stderr[-10000:]}"
    except subprocess.TimeoutExpired:
        return f"Hết thời gian chờ sau {timeout}s"

@mcp.tool()
def read_file(path: str) -> str:
    """Đọc file văn bản."""
    audit(f"READ {path}")
    return pathlib.Path(path).read_text(encoding="utf-8", errors="replace")[:200000]

@mcp.tool()
def write_file(path: str, content: str) -> str:
    """Ghi (đè) file văn bản."""
    audit(f"WRITE {path} ({len(content)} ký tự)")
    p = pathlib.Path(path)
    p.parent.mkdir(parents=True, exist_ok=True)
    p.write_text(content, encoding="utf-8")
    return f"Đã ghi {p}"

@mcp.tool()
def list_dir(path: str) -> str:
    """Liệt kê thư mục."""
    audit(f"LS {path}")
    return "\n".join(
        ("[D] " if x.is_dir() else "[F] ") + x.name
        for x in sorted(pathlib.Path(path).iterdir())
    )

if __name__ == "__main__":
    mcp.run(transport="stdio")
```
